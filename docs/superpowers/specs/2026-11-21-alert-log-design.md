# Журнал повітряних тривог за тиждень

Доповнення до `2026-11-21-air-alert-mqtt-design.md`.

## Навіщо

Користувач хоче бачити в адмінці, які тривоги були за останні 7 днів,
і щоб журнал переживав вимкнення живлення.

## Цілі / не-цілі

- Ціль: зберігати в енергонезалежній пам'яті переходи стану за 7 днів;
  показувати їх в адмінці.
- Не-ціль: експорт, графіки, статистика за довший період, публікація в MQTT.
- Анти-ціль: журнал не повинен заважати звуку і MQTT (жодних довгих
  блокувань) і не повинен псуватись при раптовому вимкненні.

## Підходи

- **А. Кільцевий буфер у NVS (обрано користувачем).** Один blob, до
  128 записів. Атомарний запис NVS, мінімум коду.
- Б. Текстовий файл у LittleFS (розділ `storage`). Без ліміту, але новий
  компонент, форматування, ручне обрізання, ризик пошкодження. Відкинуто.
- В. RAM із періодичним скиданням у флеш. Губить останні події. Відкинуто.

## Рішення

- Новий модуль `alert_log.c/.h`. Запис: `{int64_t ts; uint8_t state; uint8_t src;}`
  (`src`: 0 MQTT, 1 кнопка). Чиста логіка буфера (додати, дедуплікація,
  обрізання) окремо від NVS і тестується на хості.
- Пишеться кожна зміна стану (через callback `alert_state`), крім переходів
  у `UNKNOWN`. *Моє рішення:* і від MQTT, і від кнопок, з позначкою джерела.
- `ts`: для MQTT — час з повідомлення; для кнопок — `clock_now()`.
  *Моє рішення:* якщо час не синхронізовано (`ts == 0`), запис усе одно
  зберігається, в адмінці показується «час невідомий».
- Дедуплікація: *моє рішення* — запис з тим самим станом і тим самим `ts`,
  що й останній, не додається (retained-повідомлення після перезавантаження
  не дублює подію).
- Обрізання при кожному записі: видалити записи з `ts > 0`, старші за 7 днів
  від найновішого відомого часу (`clock_now()`, а якщо 0 — максимальний `ts`
  у буфері); при переповненні 128 — найстаріший.
- NVS: namespace `aa_log`, ключ `log`, blob; запис з задачі `notify`
  (не з контексту MQTT/таймера). `settings_erase` журнал не чіпає;
  кнопка «Очистити журнал» в адмінці — окремо (POST `/log/clear`).
- Адмінка: `GET /log` → JSON `[{"ts":..,"state":"RED","src":"mqtt"},...]`
  (новіші першими); на сторінці таблиця «Початок · Кінець · Тривалість ·
  Рівень · Джерело», зібрана в браузері з переходів (епізод = від RED/YELLOW
  до наступного CLEAR). Час у браузері за Києвом.
