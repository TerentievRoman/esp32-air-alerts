# air_alert Firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Прошивка ESP32-C3 SuperMini, яка по MQTT отримує рівень тривоги в Києві, програє відповідний трек через DFPlayer, щодня о 09:00 вмикає метроном хвилини мовчання і налаштовується через веб-адмінку.

**Architecture:** Модулі з одним призначенням у `main/`: `settings` (NVS), `wifi` (STA/AP), `admin` (HTTP + captive DNS), `clock` (SNTP), `mqtt` (підписка), `alert_state` (стан + розбір JSON), `notify` (DFPlayer/LED/кнопка у своїй задачі), `silence` (таймер 09:00). `main.c` лише запускає їх. Чиста логіка (розбір JSON, застарілість, розклад 09:00) тестується на хості звичайним gcc через `tests/host/`.

**Tech Stack:** ESP-IDF v6.1.1, C, esp_wifi, esp_http_server, esp_netif_sntp, `espressif/mqtt` та `espressif/cjson` з реєстру компонентів, NVS, esp_timer, драйвер `dfplayer.c` користувача.

**Spec:** `docs/superpowers/specs/2026-11-21-air-alert-mqtt-design.md`

## Global Constraints

- Target `esp32c3`, ESP-IDF v6.1.1, збірка `idf.py build` без помилок і без нових warning-ів у `main/`.
- Нічого блокуючого в `app_main`; DFPlayer керується лише з задачі `notify`.
- API `dfplayer.h` не змінюється.
- Усі піни та значення за замовчуванням у `main/Kconfig.projbuild` з префіксом `CONFIG_AA_`; у `.c` жодних магічних GPIO.
- Стани: `ALERT_STATE_UNKNOWN`, `ALERT_STATE_CLEAR`, `ALERT_STATE_YELLOW`, `ALERT_STATE_RED`.
- Топік стану за замовчуванням `air_alert/kyiv/state`, JSON `{"state":"CLEAR"|"YELLOW"|"RED","ts":<unix>,"src":"..."}`.
- Поріг застарілості `CONFIG_AA_STALE_ALERT_SEC` = 10800. Якщо час не синхронізовано, retained RED вважається свіжим (fail-loud).
- Хвилина мовчання: 09:00:00 Europe/Kyiv (`TZ="EET-2EEST,M3.5.0/3,M10.5.0/4"`), трек 4, пропускається якщо стан RED.
- Треки: 1 yellow, 2 red, 3 clear, 4 silence.
- LED GPIO8 active-low; кнопка GPIO9 active-low; DFPlayer UART1 TX GPIO1 / RX GPIO0.
- Секрети (паролі) ніколи не потрапляють у логи та коміти.

## Review Focus

1. Повідомлення MQTT з невідомим `state` або без `ts`: стан не змінюється, лог WARN, без краху (тест у Task 1).
2. Retained RED з `ts` старшим за поріг після перезавантаження: LED горить, сирена мовчить (тест у Task 1 + ручна перевірка Task 8).
3. Втрата Wi-Fi під час сирени: сирена дограє, після реконекту повторна retained-доставка того самого стану не запускає сирену вдруге (тест у Task 1: `alert_state_set` того самого стану повертає false).
4. Адмінка в STA без пароля або з неправильним: 401, налаштування не змінюються (перевірка Task 5).
5. Перехід через 09:00 під час відсутності синхронізації часу: таймер не ставиться, після синхронізації ставиться на найближчі 09:00 (тест `clock_seconds_until_daily` у Task 6 на межах доби).
