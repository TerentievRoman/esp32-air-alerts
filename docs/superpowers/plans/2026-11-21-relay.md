# air_alert Relay (PHP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PHP-скрипти для shared-хостингу, які приймають вебхук Порталу даних Києва і публікують retained-стан у MQTT-брокер.

**Architecture:** `hook.php` (вхід, секрет, лог, мапінг) → `mqtt_publish.php` (мінімальний MQTT 3.1.1 поверх TLS-сокета) → брокер. Чистий мапінг винесено у `map.php` і тестується `php tests/run.php`.

**Tech Stack:** PHP ≥ 7.4, `stream_socket_client`, без composer.

**Spec:** `docs/superpowers/specs/2026-11-21-air-alert-mqtt-design.md`

## Global Constraints

- Без composer, без демонів, без запису поза `relay/log/`.
- Секрети лише в `relay/config.php` (у `.gitignore`); `relay/config.example.php` у репозиторії.
- Топік `air_alert/kyiv/state`, QoS 1, retain, payload `{"state":"CLEAR"|"YELLOW"|"RED","ts":<unix>,"src":"kyiv_webhook"}`.
- Невірний секрет → HTTP 403 без логування тіла.
- Сирий запит логується в `relay/log/raw-YYYYMM.log`, кожен запис ≤ 4096 байт.

## Review Focus

1. Тіло вебхука, яке не розпізнано: HTTP 202 з `{"ok":false,"reason":"unmapped"}`, лог є, у брокер нічого не йде (тест Task 2).
2. Брокер недоступний: HTTP 502, у логу `publish failed`, без фатальної помилки PHP (ручна перевірка Task 1 з неправильним хостом).
3. Повторний однаковий вебхук: публікується знову (retained ідемпотентний), 200 (тест Task 2).
4. PUBACK не прийшов за 5 с: таймаут, false (Task 1).
5. Запит GET без секрету від сканерів: 403, лог не росте (Task 2).

### Task 2: map.php і hook.php

**Files:**
- Create: `relay/map.php`, `relay/hook.php`, `relay/tests/run.php`

**Interfaces:**
- Produces: `function map_payload_to_state(array $payload): ?string` — повертає `"RED"`, `"YELLOW"`, `"CLEAR"` або `null`. Правила (поки немає реального зразка): шукає перше з полів `state`, `status`, `type`, `event`, `alertType`, `action` (без урахування регістру); значення `start|started|alert|active|on|1|true|тривога|початок` → RED; `end|ended|clear|inactive|off|0|false|відбій|кінець` → CLEAR; `yellow|warning|attention|увага` → YELLOW; інакше null. Якщо є булеве поле `active`/`isActive`: true → RED, false → CLEAR.
- `hook.php`: читає `config.php`; перевіряє `$_GET['key']` або заголовок `X-Relay-Key` проти `secret` (hash_equals), інакше 403 і вихід; читає тіло (`php://input`), логує `date, method, ip, headers content-type, body[0..4096]`; `json_decode` (при помилці — `$payload = $_POST ?: $_GET`); `map_payload_to_state`; null → 202 `{"ok":false,"reason":"unmapped"}`; інакше `mqtt_publish` payload `{"state":..., "ts": time(), "src":"kyiv_webhook"}`; false → 502; true → 200 `{"ok":true,"state":...}`.

- [ ] **Step 1: Тести** `relay/tests/run.php` (без фреймворку, `assert` + лічильник, exit code):

```php
expect(map_payload_to_state(["status"=>"start"]), "RED");
expect(map_payload_to_state(["status"=>"END"]), "CLEAR");
expect(map_payload_to_state(["type"=>"увага"]), "YELLOW");
expect(map_payload_to_state(["active"=>true]), "RED");
expect(map_payload_to_state(["active"=>false]), "CLEAR");
expect(map_payload_to_state(["foo"=>"bar"]), null);
expect(map_payload_to_state([]), null);
```

- [ ] **Step 2: Run** `php relay/tests/run.php` → FAIL. **Step 3: Implement.** **Step 4: Run** → `OK 7/7`.
- [ ] **Step 5: Verify** `hook.php` локально через `php -S 127.0.0.1:8080 -t relay` з тестовим `config.php`: `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8080/hook.php` → `403`; `curl -s -X POST "http://127.0.0.1:8080/hook.php?key=SECRET" -H 'Content-Type: application/json' -d '{"status":"start"}'` → 200 і JSON з `RED`; `-d '{"x":1}'` → 202 `unmapped`.
- [ ] **Step 6: Commit** `git commit -m "Add webhook receiver with payload mapping"`
